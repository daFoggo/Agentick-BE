# Quality Rules

## Ruff

Use Ruff for linting and formatting:

```bash
uv run ruff check . --fix
uv run ruff format .
```

Do not run these repeatedly during docs-only work unless requested.

## Tests

Use pytest:

```bash
uv run pytest
```

Add or update tests when changing:

- Authentication or authorization behavior.
- Service business rules.
- Repository query semantics.
- Scheduler decisions.
- AI tool execution behavior that can be tested deterministically.

## SQLAlchemy Rules

Use SQLAlchemy boolean comparison helpers:

```python
Task.is_deleted.is_(False)
User.is_active.is_(True)
```

Avoid:

```python
Task.is_deleted == False
not Task.is_deleted
```

Keep repository query methods explicit when a query affects privacy, permissions, soft delete, or aggregation.

## Migration Rules

- Generate migrations only for schema changes.
- Review autogenerated migrations before keeping them.
- Avoid unrelated schema churn.
- Avoid destructive migration operations unless explicitly intended.
- Keep migration messages concise and behavior-focused.

## Review Priorities

When reviewing backend changes, check these first:

1. Layer violations.
2. Missing auth or permission checks.
3. Soft-deleted data leaking into reads.
4. Transaction boundaries around multi-write operations.
5. Response schema consistency.
6. Alembic migration correctness.
7. LLM calls used where deterministic code should decide.
8. Missing focused tests for changed behavior.
