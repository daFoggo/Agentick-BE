# Agentick Backend Agent Instructions

These instructions apply to the whole backend repository.

## Read First

Before making backend changes, read the handbook entrypoint:

- `docs/handbook/00_index.md`

Then open the specific handbook page for the task:

- Architecture or layer decisions: `docs/handbook/02_architecture.md`
- New feature work: `docs/handbook/03_feature_development.md`
- API/service/repository work: `docs/handbook/04_api_repository_service.md`
- AI agent or scheduler work: `docs/handbook/05_ai_agent_runtime.md`
- Quality, tests, migrations, review: `docs/handbook/06_quality_rules.md`

Do not create or maintain separate agent rule files for this repo. The handbook is the source of truth.

## Core Rules

- Keep the dependency direction one-way: endpoint -> service -> repository -> model.
- Endpoints own HTTP concerns, dependency injection, auth dependency selection, and `ResponseSchema` wrapping.
- Services own business orchestration, authorization checks that require domain data, cross-repository coordination, and transaction decisions.
- Repositories own SQLAlchemy query details only. Do not put HTTP concepts or business workflows in repositories.
- Schemas own request validation and response serialization. Do not return raw ORM models from endpoints without a response schema.
- Use `AppError` subclasses from `app/core/exceptions.py` for expected API failures.
- Use `UnitOfWork` when one operation must write through multiple repositories atomically.
- Keep background scheduler orchestration in `app/core/scheduler.py`.
- Keep LLM provider access behind `app/agents/llm_strategy.py`.

## API Pattern

Every endpoint should return the standard response envelope:

```python
return ResponseSchema(data=result, message="Operation completed successfully")
```

Avoid raw dictionaries for normal API responses unless the endpoint is a health/system endpoint.

Service dependencies should be wired in the endpoint module with `get_<feature>_service(...)`. Repositories should receive the current request session through `lambda: nullcontext(db)` so the service uses the same session for the request.

## Database And Migration Rules

- Models inherit from `app/model/base_model.py`.
- Use Alembic for schema changes.
- Review autogenerated migrations before keeping them.
- Use SQLAlchemy boolean filters with `.is_(True)` and `.is_(False)`, not `== True`, `== False`, or Python `not`.
- Soft-delete domains must consistently filter deleted records out of reads.

## AI Agent Rules

- Prefer deterministic Python for eligibility, filtering, scheduling, and strict business rules.
- Use the LLM for language generation, interpretation, or flexible reasoning only after deterministic checks are complete.
- Tool schemas must be explicit about UUID fields, enum-like values, dates, and required fields.
- Agent traces should use Opik decorators where useful.
- LLM JSON parsing must degrade gracefully instead of crashing application workflows on malformed model output.

## Verification

For code changes, prefer focused checks:

```bash
uv run ruff check . --fix
uv run ruff format .
uv run pytest
```

For docs-only changes, do not run Ruff or tests unless explicitly requested.
